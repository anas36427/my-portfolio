Overview

eMeter is a production-grade electricity meter management system built to handle the full lifecycle of consumer data from meter reading and billing to account management and reporting. It is my most technically ambitious project, spanning a complete backend API layer and a functional React.js frontend.

Problem Space

Electricity distribution involves complex workflows that are often handled manually or through disconnected systems:

  • • Managing thousands of consumer records with accurate billing cycles is error-prone when done manually.
  • • Meter-reading data needs to be tracked, validated, and linked to consumer accounts reliably.
  • • Different roles (admin, field officer, consumer) require different access levels and views.
  • • No centralized system meant data duplication and inconsistent records.

Backend (Django)

  • 25+ REST API endpoints with DRF
  • JWT Authentication & Token Refresh
  • Role-Based Access Control (RBAC)
  • PostgreSQL with optimized schemas

Frontend (React)

  • React.js consuming DRF API layer
  • Role-specific dashboards per user type
  • Consumer record management UI
  • Billing & meter-reading workflow views

Key Outcome

A fully functional system handling 1,000+ consumer records with role-segregated access, JWT-secured endpoints, and a clean React frontend. This project demonstrates end-to-end full-stack capability from database schema design to API development to UI integration.

Overview

cFix is a digital platform designed to streamline hostel-related processes at Aligarh Muslim University (AMU). The system replaces traditional manual workflows for complaints, hostel applications, and communication creating a smoother, more transparent, and user-friendly experience.

Problem Space

Through user interviews and process analysis (students, wardens, hostel administration):

  • • Complaints were handled manually → slow updates & no tracking.
  • • Hostel forms (leave, room change, medical) were on paper → prone to loss & delays.
  • • No centralized dashboard for wardens/admins → difficult to manage workload.
  • • Students had no visibility into status → constant follow-ups.
  • • No audit trail or proper documentation for record keeping.

Target Users

  • Students (primary users)
  • Wardens (complaint handlers)
  • Provost / DSW (escalation & approvals)
  • IT Staff (system maintenance)

Key Features

  • Role-Based Dashboards
  • Smart Complaint Submission
  • Online Application Forms
  • Real-Time Notifications

Design Process & UI

I began with grayscale wireframes focusing on form clarity, clear hierarchy, and minimal cognitive load. The high-fidelity design uses color-coding for statuses (Pending, Processing, Resolved), card-based dashboards, and WCAG 2.1 compliant typography.

Outcome & Impact

From pilot testing: Students reported less confusion & fewer follow-ups. Staff experienced faster resolution workflows. ~1.5 second average response time achieved. Centralized records improved auditing & administration.
